    Git Clone only a single branch (aka. Sparse / Shallow Clone)¶

    # clone only the remote primary HEAD (default: origin/master)
git clone <url> --single-branch

# as in:
git clone <url> --branch <branch> --single-branch <folder>

    Where: - <url> is the URL of the remote repository, and does not reference the branch cloned - <folder> is the local folder where you want to clone the repository.

    If you have git-submodules then:

    git clone --recurse-submodules --single-branch

    Get the Full Repo after a single branch clone in git¶

    If you wish to Get the Full repo then:

    git config remote.origin.fetch +refs/heads/*:refs/remotes/origin/*
git fetch --unshallow

    Reference for this trick¶

    How do I clone a single branch in Git?

    https://stackoverflow.com/a/9920956

    Squash Multiple Commits in Git (aka. Merge Commits or Git Squash / squish)¶

    git reset --soft HEAD~3 && \
git commit --edit -m"$(git log --format=%B --reverse HEAD..HEAD@{1})"

    Here the HEAD~3 indicates how many previous commits will be squashed together. In this case it shows that 3 commits from the current HEAD.

    That's the squish operation or squash operation for git. Very crucial is helping to hid the small deltas and pitfalls.

    Rescue from leaked secrets in Repositories

    This is also helpful in rescuing you when you have accidentally leaked secrets into your repository. Just use a Squash till all the commits had that secret including the one where you removed it.

    Ignore Non tracked files for status in Git¶

    git config --local status.showUntrackedFiles no
    This means that new files or ignored files.

    Change the Default branch name to main in Git¶

    Due to all folks including Github switching the default branch to main there have been lot of troubles. Here is a quick fix for the same by adding the following to .gitconfig file:

    [init]
      defaultBranch = main

    Generate Empty Commits to Initiate the CI or Action in Git¶

    Reference: https://www.freecodecamp.org/news/how-to-push-an-empty-commit-with-git/

    git commit --allow-empty -m "Empty-Commit"
# To add Signing
# git commit --allow-empty -sm "Empty-Commit"

# Finally Push the Commit
git push origin main

    Make the Git repository Super Compact : Garbage Collect / Prune¶

    # Expire all the unreachable content and pack the repo in the most
# compact way.
git gc --aggressive --prune=now

# also clear the reflog as well
git reflog expire --expire=now --all

    This would force to compress the whole data blocks again.

    Normal way to perform this¶

    git gc

    This would just remove some trailing ends but not compress the whole repo.

    Commit specific files¶

    git commit -m "current notes." file1 file2 fileN

    Revert the Commit that has not be Pushed to Remote yet¶

    git reset --soft HEAD^

    This would undo last commit and bring changes back into staging (i.e. reset to the commit one before HEAD).

    Delete the Last Commit from History in Git¶

    git reset --hard HEAD^

    This would undo last commit and destroy changes you made (i.e. reset to the commit one before HEAD).

    WARNING! Dangerous command and use it with care.

    The "Oh no I should have been working in a branch" Trick in Git¶

    # takes staged changes and 'stashes' them for later, and reverts to HEAD.
git stash

# creates new branch and switches to it, then takes the stashed changes and stages them in the new branch.   fancy!
git stash branch new-branch-name

    Stash can also save you when you wish to test out some things but not pollute the current history.

    https://wikileaks.org/ciav7p1/cms/page_1179773.html

    List files that are deleted¶

    git ls-files --deleted

    List files that are changed¶

    git ls-files --modified

    List files that are added¶

    git ls-files --others

    Add files to staging¶

    # Add deleted files to staging.
git ls-files --deleted -z | xargs -r -0 git rm

# Add modified files to staging.
git ls-files --modified -z | xargs -r -0 git add
# or
git add -u

# Add new files to staging.
git ls-files --others -z | xargs -r -0 git add

    Commit what are in staging¶

    git commit -m 'Commit comment here....'

    Auto switch Git configuration for different Emails and Usernames on same computer¶

    Article Inspiration: https://blog.hao.dev/how-to-use-different-git-emails-for-personal-and-work-repositories-on-the-same-machine

    PDF Copy.

    The supporting Git documentation https://git-scm.com/docs/git-config#_includes.

    Create 2 User files:

    • .gitconfig-default-user

      [user]
    name = "Default User"
    email = "default@git-source.com"

    • .gitconfig-another-user

      [user]
    name = "Another User"
    email = "another@git-source.com"

    The above files are dependent on your specific use case and credentials.

    Next, we update the .gitconfig file:

    • Remove the [user] section in the .gitconfig file.

    • Replace it with the following:

      [include]
    path = .gitconfig-default-user
[includeIf "hasconfig:remote.*.url:**/Another/**"]
    path = .gitconfig-another-user
[includeIf "gitdir:~/AnotherUser-projects/"]
    path = .gitconfig-another-user
[includeIf "gitdir:/mnt/Office-Projects/"]
    path = .gitconfig-another-user

    In the above code the Default User would be included normally. However the definition would be override when a particular repository path like ~/AnotherUser-projects/ is found. Also in case the remote URL can hint at switching the user.

    Changing Author and Committer name/email for multiple commits in Git History¶

    Reference: https://stackoverflow.com/questions/750172/how-do-i-change-the-author-and-committer-name-email-for-multiple-commits

    PDF File For the same.

    1. Set the correct user.name and user.email
    git config --global user.name "New Author Name"

    git config --global user.email "<email@address.example>"
    1. Command to Apply for all Commits in the repository:
    git rebase -r --root --exec "git commit --amend --no-edit --reset-author"

    OR

    Only for a single commit or the last commit:

    git commit --amend --no-edit --reset-author

    OR

    Only a few commits before the bad commit:

    git rebase -r <some commit before all of your bad commits> \
    --exec 'git commit --amend --no-edit --reset-author'

    The -r flags allows to go back in time from the current HEAD.

    Git Migration from Bitbucket to Github¶

    1. Clone the Repository from Bitbucket

      git clone --recursive ssh-path-from-bitbucket

    2. Pull all the Branches

      git pull --all

    3. List all the Branches

      git branch -r

    4. Checkout all Branches in the repository one by one

      git checkout branch-name

      Note: Make sure to go back to the master branch at the end.

    5. Remove the Origin from Bitbucket

      git remote remove origin

    6. Add the New Origin for Github

      git remote add origin ssh-path-from-github

    7. Rename the Master branch to Main

      git branch -M main

    8. Push all branches to Github

      git push --all origin -u

    Reference: https://stackoverflow.com/questions/1914579/set-up-git-to-pull-and-push-all-branches

    Script to perform the Git Migration between Bitbucket and Github¶

    Here is the file for download in Archive format. This includes more utilities to list out the repositories for an Organization in Github. Plus an utility to do the Repository Migration using a CSV file.

    Let's look at the bare minimum process of doing the Git Repository Migration.

    repo-migrate.sh
    #!/bin/bash
##
# Migrate a Git repository from one remote to another
#
# Usage: ./repo-migrate.sh <repository_url> <new_origin_url>
#
# Example:
# ./repo-migrate.sh
#
#  This would print the help message
#
# Example:
# ./repo-migrate.sh git@somehub.com:user/repo.git git@otherhub.com:user2/repo.git
#
# This would migrate the repository from somehub to
#  otherhub were user2 has access to both the repositories.
#

# Check if repository URL and new origin URL are provided
if [ -z "$1" ] || [ -z "$2" ]; then
  echo "Usage: $0 <repository_url> <new_origin_url>"
  exit 1
fi

# Clone the repository
git clone $1
# Extract the repository name from the URL
repo_name=$(basename $1 .git)

# Change into the repository directory
cd $repo_name

# Fetch all branches and tags
git fetch --all
git fetch --all --tags

# Get a list of all branches except master and origin/HEAD
branches=$(git branch -r | grep -v 'origin/master' | grep -v 'origin/HEAD' | sed 's/origin\///')

# Checkout each branch one by one
for branch in $branches; do
  git checkout $branch
done

# Get a list of all tags
tags=$(git tag)

# Checkout each tag one by one
for tag in $tags; do
  git checkout $tag
done

# Print all the branches
echo
echo " -- Branches - Remote"
echo
git branch -r

echo
echo " -- Branches - Local"
echo
git branch -r

echo
echo " -- Tags"
echo
git tag -l

echo

# Check if master branch exists and checkout if it does
if git show-ref --verify --quiet refs/heads/master; then
  # Checkout the master branch last
  git checkout master
  # Rename master to main
  git branch -m master main
else
  git checkout main
fi

# Change the remote origin to the new URL
git remote set-url origin $2

# Check the number of branches
branch_count=$(git branch | wc -l)

# Push to the new origin
if [ $branch_count -eq 1 ]; then
  git push -u origin main
else
  git push --all origin -u
fi

# Push all tags to the new origin
git push --tags origin

# Clean up afterwards
cd ..
rm -rf $repo_name
